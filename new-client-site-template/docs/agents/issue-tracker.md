# Issue tracker

This repository uses local markdown files as its issue tracker.

## Location

Store issues and related planning artifacts under `.scratch/<feature>/` in the repository. Use one feature folder per piece of work.

## Workflow

Create a feature folder with a short descriptive name, then add the issue, notes, or specification files needed for the work. Keep temporary planning material in `.scratch/` until it is either implemented or intentionally discarded.

There is no external issue tracker or CLI integration configured for this starter template.

## Pull requests

Pull requests are not treated as an issue intake surface by default.
