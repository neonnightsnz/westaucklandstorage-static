# Domain documentation

This repository uses a single-context documentation layout.

## Layout

- `CONTEXT.md` contains the project's domain model, goals, vocabulary, rules, and integrations.
- `docs/adr/` contains architecture decision records.

## Consumer rules

Read `CONTEXT.md` before making domain-level changes. Check relevant records in `docs/adr/` before changing an established architectural decision. Keep the context concise and update it when the project's terminology, rules, or boundaries change.

Architecture decisions should record the decision, context, alternatives considered, and consequences. Do not rewrite an accepted ADR; add a new ADR when a decision changes.
